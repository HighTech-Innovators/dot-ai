# Flutter Testing

How tests are written and run. Complements the global testing
posture in `global/06-testing.md`.

---

## Frameworks

- **`flutter_test` (bundled with the SDK) is the only test
  framework** until a real need is proven. Do not add
  `integration_test`, `mockito`, `mocktail`, or similar without
  escalating to the architect first, per `01-constraints.md`.
- **Widget tests use `WidgetTester` + `pumpWidget`.** Unit tests
  for pure Dart logic that does not touch the widget tree do not
  need to pump anything — keep them plain `test()` blocks.

## What to test at which level

- **Pure Dart logic** (models, calculations, formatters) gets
  plain unit tests — no `WidgetTester` involved.
- **Widgets** get a render test that pumps the widget with
  representative data and asserts on what's found via `find.text`,
  `find.byType`, or `find.bySemanticsLabel` — prefer semantics-based
  finders over `find.byKey` unless nothing else identifies the
  widget.
- **Screens** get a smoke test (pumps without throwing, given
  sensible arguments) plus one test per distinct user-observable
  flow on that screen.

## Test file layout

- Tests colocate under `test/`, mirroring the `lib/` path:
  `lib/features/foo/screens/foo_screen.dart` →
  `test/features/foo/screens/foo_screen_test.dart`. The default
  `test/widget_test.dart` generated by `flutter create`, mirroring
  `lib/main.dart`, is the pattern to follow.

## Golden tests

- **Not mandated.** Introduce golden (image-diff) tests only with
  an explicit reason — they require committed baseline images and
  platform-consistent rendering, and are a maintenance cost, not a
  default.

## What this does not cover

Widget-authoring conventions that make a widget testable in the
